# @pqc-sdk/langchain

LangChain / LangGraph tools for post-quantum cryptography from
[`@pqc-sdk/core`](https://www.npmjs.com/package/@pqc-sdk/core): hybrid X-Wing
and ML-KEM encryption (FIPS 203), ML-DSA signatures (FIPS 204). The tools are
`StructuredToolInterface`s, usable with `createReactAgent`, `ToolNode`, or
anything built on `@langchain/core`.

**Secret keys never pass through the model context.** No tool accepts or
returns secret key material. Tools refer to secret keys by `keyId`, and the
keys move only through two callbacks you provide. This package does no I/O:
where keys live — a secrets manager, a KMS-wrapped database, an encrypted
file — is your decision.

## Install

```bash
npm install @pqc-sdk/langchain @pqc-sdk/core @langchain/core zod
```

## Usage

```ts
import { createReactAgent } from '@langchain/langgraph/prebuilt';
import type { SecretKey } from '@pqc-sdk/core';
import { createPqcTools } from '@pqc-sdk/langchain';

// Demo only: an in-memory Map loses every key when the process restarts, and
// anything encrypted to those keys can then never be decrypted. Use durable
// storage (a secrets manager, a KMS-wrapped database) in real deployments.
const vault = new Map<string, SecretKey>();

const tools = createPqcTools({
  // Called on every pqc_decrypt / pqc_sign.
  resolveSecretKey: async (keyId) => {
    const key = vault.get(keyId);
    if (!key) throw new Error(`unknown key ${keyId}`);
    return key;
  },
  // Receives each key generated by pqc_keygen. Omit it to leave pqc_keygen out.
  onSecretKey: async (keyId, secretKey) => {
    vault.set(keyId, secretKey);
  },
  // enableSign: true, // pqc_sign is excluded unless you opt in
});

const agent = createReactAgent({ llm, tools });
```

To give the agent keys you already have, store them under a `keyId` of your
choice and tell the model that id — the key itself never needs to reach it.

### Options

| Option             | Type                                          | Notes                                                                                                                  |
| ------------------ | --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `resolveSecretKey` | `(keyId) => Promise<SecretKey>`               | Required. Throw if the key does not exist. The `keyId` is already validated against `KEY_ID_PATTERN`.                  |
| `onSecretKey`      | `(keyId, secretKey) => void \| Promise<void>` | Optional. `pqc_keygen` returns the public key only after this resolves; if it throws, the model gets an error, no key. |
| `enableSign`       | `boolean`                                     | Default `false`. Adds `pqc_sign`.                                                                                      |

**Valid key ids** (`KEY_ID_PATTERN`): 1–64 characters, a letter or digit
first, then letters, digits, `_` or `-`. Anything else is rejected before
`resolveSecretKey` is called, so your resolver never sees `/`, `\` or `..`.
Generated ids look like `x-wing-3f9a1c2b7d4e`.

### Tools

| Tool             | Input                                                          | Output                                                                         |
| ---------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `pqc_keygen`     | `algorithm` (default `x-wing`) — only with `onSecretKey`       | `{ keyId, algorithm, publicToken }`                                            |
| `pqc_encrypt`    | `publicToken` + exactly one of `plaintext` / `plaintextBase64` | `{ ciphertextHex }`                                                            |
| `pqc_decrypt`    | `keyId`, `ciphertextHex`                                       | `{ encoding: "utf8", plaintext }` or `{ encoding: "base64", plaintextBase64 }` |
| `pqc_sign`       | `keyId`, `message` — only with `enableSign: true`              | `{ signatureHex }`                                                             |
| `pqc_verify`     | `message`, `signatureHex`, `publicToken`                       | `{ verified }`                                                                 |
| `pqc_algorithms` | —                                                              | `{ supported, fips }`                                                          |

`pqcEncryptTool`, `pqcVerifyTool` and `pqcAlgorithmsTool` need no keys and
are also exported on their own.

Failures are thrown as `Error`s whose message starts with `PqcError[CODE]:`
— the `@pqc-sdk/core` codes plus `INVALID_ARGUMENT`, `INVALID_CIPHERTEXT`,
`KEY_NOT_FOUND` (your resolver threw, or returned something that is not a
secret key; its own message is kept off the model and available as `cause`)
and `KEY_STORAGE_FAILED` (`onSecretKey` threw).

## What this does not protect

**`pqc_decrypt` is a decryption oracle for the model.** The callbacks keep the
_key_ out of the model context, but whatever the model decrypts, it reads.
Only resolve keys whose plaintexts the model is allowed to see. The same
reasoning is why `pqc_sign` is off by default: a signature is a statement made
under the key owner's identity, and enabling it is your decision.

## Migrating from 0.2.x

0.3.0 replaces the stateless secret-token tools with a factory.

| 0.2.x                                                  | 0.3.0                                                                                    |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `pqcTools`                                             | `createPqcTools({ resolveSecretKey, onSecretKey })`                                      |
| `pqcKeygenTool` → `{ publicToken, secretToken }`       | `pqc_keygen` → `{ keyId, algorithm, publicToken }`; the secret key goes to `onSecretKey` |
| `pqcDecryptTool { ciphertextHex, secretToken }`        | `pqc_decrypt { keyId, ciphertextHex }`                                                   |
| `pqcDecryptTool` → `{ plaintext }`                     | `{ encoding: "utf8", plaintext }` or `{ encoding: "base64", plaintextBase64 }`           |
| `pqcSignTool { message, secretToken }`                 | `pqc_sign { keyId, message }`, only with `enableSign: true`                              |
| `pqcEncryptTool`, `pqcVerifyTool`, `pqcAlgorithmsTool` | unchanged exports; `pqcEncryptTool` also accepts `plaintextBase64`                       |

Existing secret tokens can be loaded with `pqc.keys.deserialize(token)` inside
your `resolveSecretKey`, from wherever you store them. Because 0.2.x returned
secret tokens to the model, treat keys generated through it as exposed: rotate
them if the data they protect matters.

0.3.0 also ships TypeScript declarations (`dist/index.d.ts`); 0.2.x declared
them in `package.json` but did not include the file.
